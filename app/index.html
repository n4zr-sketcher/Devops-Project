01 — ARCHITECTURAL PATTERN

Zero-Downtime Deployment Lifecycle

Eliminates error-prone manual server management with auditable, reproducible releases.

The Problem: Manual Deployment

Direct file modifications and manual restarts cause server configuration drift, inconsistent permissions, and immediately disconnect in-flight HTTP requests.

Legacy Antipattern

The Solution: Automated CI/CD

Terraform guarantees infrastructure consistency. Jenkins validates code syntax, stages immutable release folders, and tests artifacts before public routing.

Terraform + Jenkins

The Guarantee: Atomic Symlink Swap

/var/www/app is swapped atomically via mv -Tf. Nginx gracefully reloads workers, keeping open connections intact with zero dropped requests.

Engineering Detail: Graceful Reload vs Server Restart

Executing systemctl restart nginx abruptly drops all open TCP connections and active clients. In contrast, systemctl reload nginx validates the syntax of /etc/nginx/, starts new worker processes attached to the freshly symlinked release folder, and lets existing workers terminate gracefully only after finishing their in-flight requests.

Atomic Symlink Architecture

Nginx serves web assets from an active release symlink. Releases are immutable and isolated: 

/var/www/
├── releases/
│   ├── release-20261024190726/
│   └── release-20261024193024/  <-- immutable release
└── app ───────> releases/release-20261024193024/ (active)
  1. Stage: Release files copied to /var/www/releases/release-<id>.
  2. Validate: Nginx configuration tested with nginx -t.
  3. Atomic Switch: Symlink updated via mv -Tf in 1 kernel operation.
  4. Graceful Reload: systemctl reload nginx serves new release without dropped requests.

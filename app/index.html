01 — Introduction

From code to cloud, without manual steps

This project replaces the traditional "edit files, copy them to a server, restart the web server" routine with a fully automated delivery pipeline. The goal is not just to host a website, but to demonstrate how modern DevOps practice — infrastructure as code, continuous integration and continuous delivery — works end to end.

Problem

Manual deployment is slow and error-prone

Copying files by hand means the live server and the source repository can drift apart. A forgotten restart leaves the site serving stale content, and nobody knows exactly which version is running.

Solution

A reproducible, automated pipeline

Terraform describes the entire Azure environment as code, so it can be recreated at any time. Jenkins reacts to a GitHub push, proves the code is sound, and publishes it to the server in a single audited, repeatable action.

Outcome

Every push is deployed and verified

Each successful run publishes an immutable release folder, atomically switches the live symlink and gracefully reloads Nginx. The pipeline then verifies the response over HTTP, so a green build genuinely means the website is serving the new content.

02 — Continuous Integration & Delivery

The Jenkins pipeline

The Jenkinsfile in the repository describes the delivery process as code. It runs six stages; if any stage fails, the pipeline stops immediately and the live website is left untouched.

  1. 01

    Checkout

    Clone the latest commit from GitHub using a stored credential.

  2. 02

    Validate

    Assert that index.html, style.css and script.js all exist.

  3. 03

    Test

    Run static checks on the HTML, CSS and JavaScript before anything ships.

  4. 04

    Deploy

    Transfer the files to the Ubuntu VM over an authenticated SSH channel.

  5. 05

    Reload

    Atomically swap the release and gracefully reload Nginx — no downtime.

  6. 06

    Verify

    Request the live URL and confirm it serves the freshly deployed content.

Why a graceful reload?

systemctl reload nginx tells Nginx to pick up the new configuration and to finish the requests that are already in flight. A restart would terminate every open connection, which is exactly the kind of avoidable interruption this project is designed to eliminate.

03 — Tools & Technologies

Technology stack

Each tool solves one specific problem in the chain, and together they cover the full lifecycle from source code to a running production-style server.

Terraform

Infrastructure as Code

Describes the Resource Group, Virtual Network, Subnet, Network Security Group, Public IP, Network Interface and Ubuntu VM declaratively. The same configuration produces the same environment every time, and a single terraform destroy removes it all.

  • provider.tf
  • main.tf
  • outputs.tf
  • state files

Microsoft Azure

Cloud Platform

Hosts the application. Traffic is controlled by a Network Security Group that permits HTTP to the world but restricts SSH to a single known IP address. Cloud-init installs and configures Nginx during the very first boot.

  • Resource Group
  • VNet / Subnet
  • NSG rules
  • Ubuntu 22.04

Jenkins

CI/CD Orchestrator

Executes the declarative pipeline. Secrets such as the SSH private key and the server host key are kept in the Jenkins credential store, never in the repository, and are masked in the console output.

  • Declarative pipeline
  • Credentials store
  • Poll SCM / Webhook
  • Blue Ocean

GitHub

Version Control & Trigger

Holds the source of truth and the pipeline definition. A webhook (or, for a laptop that is not reachable from the internet, a scheduled Poll SCM scan) notifies Jenkins the moment new code is pushed.

  • Git
  • Webhooks
  • Push triggers
  • Branch protection
